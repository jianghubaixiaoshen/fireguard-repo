# 4G 火焰报警装置 · 新手踩坑实录

What If Lab AI 硬件创意黑客松参赛作品（陪跑向 · 实录型）。

一句话：**报警这事，不该看网的脸色。**
KY-026 见火即报，AHT20 顺手测温湿度，全程走 4G 上云，手机弹窗。
WiFi 在哪、有没有宽带，根本无所谓。

本仓库的价值一半在装置，一半在把每个坑摊开写清楚——
文中所有结论都来自一周实测，不是"应该可以"，是"实测如此"。
资料里的默认值只能当起点，最终以手上模块的实测行为为准。

## 仓库结构

```
firmware/            设备固件（QuecPython）
  main.py            主循环：火焰 GPIO + AHT20 → sendTsl + 看板双通道
  config.py          引脚 / 阈值 / 节流 / 平台凭据（留空，勿提交真实值）
  lib/aht20.py       AHT20 驱动（I2C1 实测版，busy 位检查 + 容错降级）
cloud/               云端演示服务（FastAPI + SQLite）
  app.py             MOCK=1 内置模拟器按真实节拍出数；MOCK=0 接真机 MQTT
  static/index.html  现场看板：火焰状态灯、温湿度曲线、告警记录、点火按钮
docs/
  接线与排错对照.md   引脚可用性表 + 四个反直觉坑的复现路径
```

## 数据链路

```
KY-026 DO(高有效) → GPIO31 中断读 ┐
AHT20(I2C1,0x38)  → 温湿度        ┴→ QuecPython 主循环 → 60s 告警节流
   → 4G 拨号 + 动态注册 → 移远 IoT 平台 sendTsl(功能ID 1/2/3)
   → 平台属性联动 fire=true → 手机 APP 弹窗（固件零推送代码）
   → 同时 POST /api/ingest 进自建看板（与模拟器同一入库路径）
```

## 演示模式（设备不在手边也能跑）

云端内置模拟器，按真机节拍出数（2s/帧）：温度在室温基线上正弦漂移加噪声、
湿度反向微动、火焰按概率偶发；也可手动点火：

```bash
cd cloud
MOCK=1 PORT=8100 python -m uvicorn app:app --port 8100
# 浏览器打开 http://<服务器>:8100（火山云演示机已挂 nginx 根路径：http://163.7.11.61 直达）
# 点火（录屏用）：
curl -X POST "http://<服务器>:8100/api/ignite?seconds=5"
```

阈值、节流、告警联动逻辑与真机固件同一份实现；设备接入后走
`POST /api/ingest`，链路不变，看板不用改。

## 实测结论速查（详见 docs/）

| 项 | 结论 | 常见误传 |
|---|---|---|
| 火焰有效电平 | **高**（见火=1） | 该型号存在输出低电平的批次，不可默认 |
| 火焰可用脚 | 丝印 4 = GPIO31 | 丝印 5 是 STATUS、丝印 6 被钳低 |
| AHT20 总线 | I2C1（丝印 16/17） | 默认扫 I2C0 读出全 0 |
| 认证 -5894 | 事件码 10425 = 签名未通过，密钥抄错 | 误当网络问题查几小时 |
| "在线"判定 | 板子读数与云端属性日志对得上才算 | APP 显示在线可能是幽灵会话 |
| 真重启 | `machine.WDT()` | 固件无 power 模块，重启接口是空喊 |
| 防风火机 | 近红外方案对其不敏感 | 误判模块坏了 |

## QuecPython 与 MicroPython 差异（照旧习惯写会翻车）

- 没有 `os` 模块；`sys.path` 需手动 `append('/usr')`
- 上拉常量是 `Pin.PULL_PU`，不是 `PULL_UP`
- `utime.time()` 返回开机秒数；墙钟用 `localtime()`、epoch 用 `mktime(localtime())`
- `sendTsl` 的键必须是**整数**功能 ID；字符串 TypeError，裸 JSON 被静默丢弃

## 平台控制台注意

「修改设备信息 / 生成二维码 / 绑 SN」都会重置 MQTT 会话，
把板子那条连接变成幽灵（TCP 连着、SDK 自认在线、平台不认、数据被悄悄丢掉）。
设备在线跑着的时候能不点就不点。动态注册须打开「缺省认证书免预写入」开关。
查数据是否真入库，只看**属性日志** tab，业务日志里透传只有一行「上行」。

APP 绑定时先看 DeviceKey：`VDU` 开头是平台生成的虚拟设备（空壳，面板永远 0），
真设备的 DeviceKey 就是模组 IMEI。

## 凭据安全

`config.py` 里 `PRODUCT_KEY` / `PRODUCT_SECRET` / `DEVICE_KEY` 一律留空，
真实值只写在设备端本地与服务器环境变量里，**不进版本库**。
另：密钥永远复制粘贴，不要从邮件截图手抄（l / 1 / I 分不清，会白熬一夜）。
